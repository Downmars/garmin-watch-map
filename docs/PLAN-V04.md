# v0.4 研究方案：地图缩放与浏览

日期：2026-11-06（Asia/Shanghai）。目标机型：普通 Forerunner 255。研究基线：v0.3.0-alpha.3，应用提交 `93d0f1ca9d3eec059d1233d7fb1dcc72d248dbdf`。用户已反馈功能暂且正常，并明确选择下一版优先地图缩放与浏览。本文描述拟实现行为，不代表已交付功能。

## 建议范围

v0.4 首先解决“看不远、缺少尺度、浏览仍有多余工作”。先交付街道/概览两级底图、比例尺与直接定位可见瓦片；验证通过后，再增加最近轨迹的概览入口。多次活动归档和路线导航分别保留后续版本研究，避免同时改变恢复数据格式与地图坐标体系。

| 优先级 | 功能 | 用户能得到什么 | 完成条件 |
|---|---|---|---|
| P0 | 街道 z15 / 概览 z13 两级地图 | 放大看街道、缩小看周边，缩放时保持当前浏览中心 | 同一点不跳动；连续切换不丢定位、轨迹或 FIT 状态 |
| P0 | 动态比例尺 | 看懂地图上大约 200 m / 1 km 的长度 | 标尺长度与当前级别、中心纬度一致 |
| P0 | 可见瓦片直索引、限制单次资源准备工作 | 减少浏览时不必要的扫描与资源加载 | 对照测量有收益，真实事件流程无 Watchdog |
| P1 | 菜单“查看最近轨迹” | 明确找到上次保留的轨迹；需要时看完整保留段的形状 | 不开始新运动、不改动摘要，暂停/失联断段仍保留 |
| P1 | 地图信息页与紧凑浏览提示 | 查到版本、底图级别、覆盖范围和生成日期，减少地图遮挡 | 260×260 圆屏可读、许可署名持续可见 |

“最近轨迹”只表示当前保留的最多 800 条记录（含断段标记）。超过容量而被覆盖的早期点不会因缩放重新出现，不把它叫作完整运动历史。

## 设备与同类方案依据

- 本机官方 FR255 设备配置给出的 Watch App 堆限额是 524,288 B。v0.3 的正常事件检查绘图采样 113,968 B、单元存储测试采样 227,840 B，均不是持续峰值；不能把剩余差值全部分配给底图缓存。
- 官方 [MapView 支持列表](https://developer.garmin.com/connect-iq/api-docs/Toybox/WatchUi/MapView.html)包含 FR955/965，不含 FR255。因此继续使用预生成底图，不把本计划建立在高端机型的原生地图接口上。
- [Garmin 图形池说明](https://developer.garmin.com/connect-iq/articles/core-topics/Graphics.html)指出 API 4.0 起图形资源可在独立图形池中自动缓存与换入换出。[BitmapReference](https://developer.garmin.com/connect-iq/api-docs/Toybox/Graphics/BitmapReference.html)仍可能因图形池不足而失败。设计判断：保留有界资源引用，比较有无额外缓存；不强制解码并常驻全城图片，也不把普通堆采样当作全部图形内存。
- [FR255 原生课程](https://www8.garmin.com/manuals/webhelp/GUID-676967A0-1B23-4384-9BC9-76F3D643F1C8/EN-US/GUID-63B647CE-1409-4BE9-8A8B-33EFEFCBF255.html)提供课程地图平移/缩放，适合借鉴按键浏览流程；这不意味着本应用自动拥有原生课程的底图或全部数据。
- [Suunto Race](https://www.suunto.com/en-be/Support/Product-support/suunto_race/suunto_race/navigation/offline-maps/)区分缩放、平移、回中，关闭底图时仍能显示轨迹；[COROS PACE 3 与 PACE Pro](https://support.coros.com/hc/en-us/articles/31426902545428-COROS-PACE-3-vs-PACE-Pro-Comparison)也区分轨迹导航与离线地图。本项目据此把底图与轨迹概览分开；不会用其他手表的处理器宣传数字预测 FR255 的速度。

## 渭南地图级别与离线估算

按当前中心纬度 34.5°、Web Mercator 和 260 px 屏宽计算：`m/px = 156543.03392 × cos(纬度) / 2^zoom`。以下是几何估算；有效地图区域会被圆屏和提示遮挡，实际可读范围更小。

| 级别 | 中心处 m/px | 整个屏幕横向约 | 覆盖现有地理边界所需 512 px 图片 | 对应 256 px 源瓦片 |
|---|---:|---:|---:|---:|
| z15，现有街道图 | 3.9371 | 1.024 km | 11×11＝121 | 484，已有 |
| z14，备选 | 7.8742 | 2.047 km | 6×6＝36 | 144 |
| z13，推荐概览图 | 15.7484 | 4.095 km | 4×3＝12 | 48 |

采用 z13/z15 可在只增加 12 张合成底图的情况下拉开明显视野差别，先不加中间层。z13 网格按现有地图边界向外覆盖，不能简单假设等于原网格除以四；边缘资源多出的区域不扩大对用户承诺的覆盖范围。

新增图片压缩后体积尚未测量，不能用 12/121 直接推导新增 PRG 大小；总包 ≤15 MB 仍是项目目标。此次未下载新瓦片，也未生成安装包。计算数据见 [v0.4-geometry.json](research/v0.4-geometry.json)。

双级缩放最多将横向范围扩大四倍，无法保证放下任意长轨迹。“查看最近轨迹”先尝试能容纳保留点边界的底图级别；若仍放不下，进入明确标注的无底图轨迹概览，按全部保留点自动缩放，保留断段。不可悄悄裁掉端点后声称显示完整。单点、无点及跨出地图范围分别处理。

## 按键与界面草案

使用三个清楚标出的地图操作模式，避免增加尚未验证的长按组合：

| 场景 | UP / DOWN | START | BACK |
|---|---|---|---|
| 地图“上下” | 上移 / 下移 | 切到“左右” | 浏览时回中；跟随时打开菜单 |
| 地图“左右” | 左移 / 右移 | 切到“缩放” | 同上 |
| 地图“缩放” | 放大 / 缩小 | 切回“上下” | 同上 |
| 菜单 | 选择项目 | 确认 | 返回 |
| 最近轨迹概览 | 暂无平移要求 | 暂无快捷动作 | 返回进入前的地图视角 |

缩放达到最大/最小级别时保持级别并短提示，不反向循环。切换操作模式本身不改变跟随/浏览；缩放保持当前中心，手动平移进入浏览。浏览期间 GPS 可以更新位置与运动记录，但不抢走视角。回中和定位过期语义延续 v0.3；无有效定位时不显示可信实时箭头。

地图页始终显示当前模式和比例尺。历史概览可采用圆屏内的 180×160 px 安全绘图区预案，将状态和许可放在其外；需用实际中文字体及圆屏截图核对，不承诺现有大块 HUD 可直接复用。菜单增加“查看最近轨迹”和“地图信息”。暂不调整自动回中时间，也不引入触屏操作。

记录中将概览入口标为“本次轨迹概览”，使用当前轨迹；结束后才称“最近轨迹”。概览只改变视角，不能暂停 FIT、覆盖当前记录或把旧摘要载入正在记录的缓冲。

## 实现切分与风险控制

1. **统一坐标参照。** 继续以 z15 世界坐标保存视口中心和轨迹投影缓存；z13 绘制时乘 1/4。缩放不重投影整条轨迹，不用经纬度来回换算累计误差。定位箭头、瓦片、轨迹和比例尺使用同一活动视口。边缘缩放保留地理中心，缺图区域明确留空或提示，避免用新的夹紧范围造成跳动。
2. **地图描述与资源生成。** 将单层 MapData 拆为有级别、原点、行列、覆盖范围的描述；资源 ID 含级别。构建工具独立生成两级、校验来源与范围，先完整生成临时结果再替换资源，防止当前 emit_sources 删除旧级别瓦片。保留现有 z15 数据与断点缓存。
3. **直接选择可见瓦片。** 当前刷新扫描 121 张，实际屏幕最多覆盖 4 张 512 px 瓦片。以视口计算首末行列，再按地图边界截取。本轮离线对照 2,028 个边界/随机视口，直索引与现有逐张相交检查一致；这是几何验证，不是应用性能测试，更不是帧率提升比例。
4. **资源准备有界。** [Garmin 资源指南](https://developer.garmin.com/connect-iq/articles/core-topics/Resources.html)提醒运行时加载可能昂贵。将新资源准备与重复刷新分开，单回调最多准备一张新资源；新的缩放/平移请求替代过期请求。先验证仅保留当前可见引用的方案，再测少量跨视口引用缓存；缓存键必须包括级别，禁止无上限增长或复制整屏多份缓冲。图形资源失败时提供明确降级，并验证可返回已有地图/轨迹页。
5. **历史概览按需计算。** 边界与缩放仅在轨迹变化或进入概览时更新，按小批次处理最多 800 条，不重新引入启动/退出大循环。当前摘要无完整历史日期索引，不为新增一个入口迁移全部存储结构。
6. **保留真实事件检查。** 扩展现有隔离应用，串联满容量旧摘要恢复、真实按键事件处理、100 次缩放/平移、后台定位更新、保存、退出及重开。测试处理器运行方式必须确实归还事件循环；不能只在一个单元函数里反复调用渲染后宣布通过。

最低 API 暂不提高；每个新增接口核对 FR255 与目标固件支持。BitmapReference 专属优化需能力检查或降级，不能仅凭 SDK 编译成功判断可用。

## 发布顺序与门槛

| 阶段 | 可交付范围 | 进入下一阶段前必须满足 |
|---|---|---|
| A：开发验证 | 多级地图描述、坐标变换、可见索引、合成资源用例 | 网格边界、两级同点、缩放往返、负偏移与缺图场景自动验证 |
| B：v0.4.0-alpha.1 | 两级渭南底图、比例尺、三种操作模式及浏览性能 | 旧摘要兼容；真实事件压力检查通过；PRG/源码可追溯；用户完成短程实机复测 |
| C：v0.4.0-alpha.2 | 最近轨迹入口、必要时无底图概览、地图信息页；缓存仅在实测有收益时采用 | 0/1/800 条、断段/环形覆盖、概览退出视角、低内存降级全部验证 |
| v0.4 功能验收 | 固化上述范围 | 实机 30 次交互 P95 目标≤300 ms、最慢≤1 s；100 次缩放/平移无 IQ!；恢复/退出不回归 |

所有阶段保持固定轨迹容量。普通堆峰值目标仍≤350 KiB，并单独记录图形资源异常；未知图形池容量不填写为已知数值。两小时稳定性、成对耗电与 FIT/Connect 内容核验继续保留为正式稳定发布门槛；本次“功能暂且正常”的反馈不能替代它们。

实现时间以阶段验证结果为准，暂不给固定交付日期。v0.3.0-alpha.3 包继续作为本轮回退点；本轮研究不改动其二进制或存储。

## 后续功能的研究结论

- **按日期查看多次历史：** 有价值，但需要独立的容量上限、活动索引、按需加载、删除确认和断电恢复设计。[Storage 文档](https://developer.garmin.com/connect-iq/api-docs/Toybox/Application/Storage.html)规定单值最多 32 KB、总容量因设备而异；不能把当前双槽机械复制成无限活动库。作为 v0.4.x 或独立迭代候选，再决定是否替换原 v0.5 顺序。
- **导入路线与导航：** 保留 v0.5 方向，先电脑端验证/简化 GPX，再决定叠加和偏航策略。[PersistedContent](https://developer.garmin.com/connect-iq/api-docs/Toybox/PersistedContent.html)可以枚举原生内容并启动系统意图，但 [Course 接口](https://developer.garmin.com/connect-iq/api-docs/Toybox/PersistedContent/Course.html)没有公开逐点读取方法。不能据此承诺直接读取手表全部 FIT 历史或把原生课程画到自绘底图上；原生导航跳转可作为另一个方案单独验机。
- **全城寻路/搜索、无线大地图下载、整屏旋转：** 不进入 v0.4。缺少道路拓扑、坐标/资源预算与实测证据，先完成当前浏览需求。

地图源沿用 OSM France HOT 时，需要继续遵守其 [服务规则](https://www.openstreetmap.fr/usage/)中的可见署名、适量流量和识别应用的 User-Agent。研究阶段不请求新增瓦片；下一步构建只取所需缺失瓦片，不能据此推广成任意区域的批量下载器。用户私钥、个人轨迹和原始错误日志不进入仓库。
