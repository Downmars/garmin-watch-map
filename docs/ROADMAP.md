# FR255 离线地图迭代计划

更新：2026-11-06。目标机型：普通 Forerunner 255。Fork：<https://github.com/Downmars/garmin-watch-map>。

## 目标与边界

把渭南示例发展为可以持续维护的按键离线地图：定位状态可信、可自由浏览、可保留运动轨迹，随后增加分级地图和预先准备的路线导航。每一版都保留可回退的构建。先用 FR255 实机数据决定性能方案，再考虑其他机型。

当前功能基线为已合入 main 的 v0.2.0-alpha.2，见 [验收记录](acceptance-v0.2.md)。v0.3.0-alpha.3 包含运动记录、简化轨迹恢复、平移优化及启动/退出超时修复。alpha.2 收到长轨迹启动 Watchdog 日志，停止推荐安装；alpha.3 的实机启动/平移/退出、续航、长时间稳定性及 FIT 内容/同步验收仍待完成。

## 设备约束与取舍

| 已确认事实 | 设计约束 |
|---|---|
| FR255：260×260、64 色 MIP、无触屏 | 五键完成全部操作；高对比线条和短中文状态；优先北向固定，避免每帧旋转底图。 |
| 当前官方设备配置：Watch App 524,288 B；Data Field 262,144 B | 分别按 512 KiB、256 KiB 预算。应用内存与 PRG 包体大小分开测量；不能把 9 MB 包体当成运行内存。 |
| 当前设备配置 API level 5.2；运行固件可能不同 | 编译器版本不等于手表固件/API；新 API 必须查设备支持并有降级方案。暂不靠提高最低 API 来解决问题。 |
| FR255 不在原生 `WatchUi.MapView` 支持列表；FR955/965 等在列表内 | FR255 继续使用自己的离线底图渲染。未来高级机型可实现独立的原生地图后端，不能宣称所有 CIQ 都不支持地图。 |
| `Application.Storage` 单个值上限 32 KB | 只存有界的设置/恢复摘要/简化轨迹，规划分块、版本号、校验与双槽写入；不把无限历史塞进一个值。 |
| SDK 提供 `ActivityRecording`，FR255 有支持 | 完整运动记录优先通过 FIT 会话；屏幕上简化轨迹与完整记录分离。与原生跑步并行使用的方案要单独验证。 |

来源与机型对比见 [RESEARCH.md](RESEARCH.md)。CPU 频率、实际可用包体上限、续航与地图解码成本缺乏本项目实测，不能用推测数值作为承诺。

## 借鉴其他手表的方式

- **FR255 原生课程 / COROS PACE 3**：预先准备路线，手表负责跟随、距离与偏航提示；先实现轻量轨迹导航，不在手表上计算全城道路路径。
- **Suunto Race**：区分地图浏览与定位跟随，允许手动回中和设置回中时间；在 FR255 上改为按键菜单，而不是复制触屏/旋钮交互。
- **COROS PACE Pro / Suunto Race**：底图与路线是独立图层；没有底图时仍能显示路线、轨迹及方向。
- **FR955/965 原生地图**：后续作为有地图硬件的适配方向，FR255 的版本不依赖其专属 API。

## 分阶段交付

各阶段先满足验收，再进入下一阶段；下列时间是工作量级估计，不是自动执行日程。

| 版本 | 范围 | 主要验收 | 依赖 / 估计 |
|---|---|---|---|
| **v0.1.0-weinan 基线** | 保存已交付源码、地图配置、修复记录、构建哈希 | 4 项构建工具测试、FR255 编译、模拟器轨迹回放；保留原 PRG | 已完成本地基线；实机待验证 |
| **v0.2 定位与浏览可靠性** | GPS 等待/正常/弱信号/过期状态，拒绝旧定位，失联后重建里程起点，越界提示，浏览锁定与按键回中 | 自动场景覆盖空值、弱信号、10 秒中断、恢复、越界；浏览 30 秒不被拉回；有效定位恢复后正常跟随 | v0.1；约 2–4 个开发日；本次启动 alpha |
| **v0.3 轨迹与记录** | 有界轨迹环形缓冲、断段标记；恢复摘要；开始/暂停/保存/丢弃 FIT 会话；明确退出行为 | 2 小时记录无增长泄漏；重启恢复摘要；保存的活动在 Garmin Connect 中可读；暂停期间不累计 | v0.2；约 4–7 日；先验证 FIT 权限和会话冲突 |
| **v0.4 分级底图与性能** | z13 概览 + z15 街道；按键切换级别；比例尺；可见瓦片直索引；有限资源缓存试验；地图日期/范围元数据 | 两级同点对齐；100 次缩放和平移不崩溃；满足内存/按键/耗电验收；低内存退回无缓存模式 | v0.2 性能基线；约 4–7 日；不要同时下载所有级别 |
| **v0.5 预设路线导航** | 电脑端 GPX 校验与简化，路线叠加、剩余距离、偏航提醒、起终点；先按城市包构建时导入 | 交叉/折返路线不误跳段；偏航连续多次确认且冷却提醒；无底图可显示路线；断 GPS 不报假偏航 | v0.3–v0.4；约 5–8 日 |
| **v1.0 稳定版** | 打包可复现、迁移/回退说明、安装排障、实机矩阵、可选择的地图样式；独立审核 Data Field 原型 | 至少 3 次城市路线 + 1 次 2 小时测试；实机预算达标；无未解释崩溃；许可与版本完整 | 各版本验收齐全后发布 |

v0.2 的 alpha 不宣称已经实现轨迹持久化、FIT、缩放、路线规划或省电。每个版本的完成项只由 CHANGELOG 和验收记录决定。

## 性能预算（项目目标，非已经测得的结果）

| 指标 | 初始门槛 | 测法 / 失败时处理 |
|---|---|---|
| Watch App 峰值堆 | ≤350 KiB，至少留下约 160 KiB 余量 | simulator System.getSystemStats + 实机诊断，长轨迹/菜单/切图组合压力；超限先收紧缓存和点数 |
| Data Field 峰值堆 | ≤170 KiB，单独原型验证 | 不能复用 Watch App 的内存结论；不通过就暂不发布字段版 |
| 按键到画面更新 | P95 ≤300 ms；最慢不超过 1 s | 实机 30 次平移/菜单操作视频或仪表；模拟器时延不能替代实机 |
| 更新频率 | 普通定位最多 1 Hz；静止时按状态/方向变化重绘 | 定位采样与绘图节流分开；不通过降低定位频率掩盖绘图问题 |
| 稳定性 | 2 小时、800 点上限压力，无未解释内存增长或崩溃 | 相同输入重复运行；保存最低剩余内存与错误日志 |
| 续航 | 与同 GPS 配置的 v0.1 比较，2 小时额外耗电目标≤2 个百分点 | 相同背光、卫星配置、路线、温度条件；至少 3 对样本。电量颗粒度不足时延长测试，不宣称精确小时数 |
| 首包与地图 | 当前单层约 9.31 MB；双层初始目标≤15 MB | 分别记录字节数、安装时间、可用空间；这些是目标，不是设备硬限制 |

## 技术拆分

- `FixState`：只接收坐标、质量、时间；可注入时间完成确定性测试。显示状态与距离接受规则分开。
- `TrackModel`：距离过滤、断段、环形缓冲；不直接操作 UI。屏幕简化轨迹不能作为 FIT 全轨迹替代品。
- `MapViewport`：跟随/浏览状态、范围、级别和投影；越界时显示状态，不夹住真实定位后伪装成仍在范围内。
- `MapRenderer`：按可见范围计算瓦片索引；先测 `BitmapReference` 与资源池表现，再决定是否添加 2–4 个条目的缓存；不预解码全城。
- `RecordingController`（v0.3）：FIT 会话及退出/恢复策略；存储异常需要可见反馈，不静默丢失用户记录。
- 构建工具：城市配置、地图元数据、原始数据/底图许可、版本与校验；CI 使用假瓦片，不请求公共瓦片服务器。

## 明确暂缓

全城道路自动寻路、地址/POI 全文检索、实时交通、整屏旋转底图、无线下载全城地图、所有 Garmin 型号同时适配。本阶段先完成 FR255 的核心体验。手机或电脑端可做重计算，手表使用经过验证的小数据包。

## 发布流程与人工操作

1. `main` 保存已验证基线；每个迭代使用 `iteration/vX.Y-*` 分支和 fork 内 PR。
2. CI：Python 单元测试、语法、XML、禁止提交密钥/生成底图；Monkey C 单元测试与编译在装有 SDK/设备配置的本机运行，并附日志。CI 通过不代表实机通过。
3. 每个候选包记录源码提交、SDK、设备配置、城市范围、PRG SHA-256、测试项与未通过项；检查候选包与报告哈希一致。
4. 用户负责网页登录、fork 页面、USB 安装、实机路线/耗电测试；开发侧负责源码、构建、模拟器与结果分析。
5. 实机未验收的包标记 `alpha`；只有明确的验收结果才进入稳定发布。上游 PR、应用商店发布和自动安装到手表都不是本计划的默认步骤。

具体测试场景见 [VALIDATION.md](VALIDATION.md)，待办见 [BACKLOG.md](BACKLOG.md)。
