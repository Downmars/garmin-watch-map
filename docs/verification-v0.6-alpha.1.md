# v0.6.0-alpha.1 验证记录

验证环境：Windows x64，Connect IQ SDK 9.3.0，普通 FR255 官方设备配置，Java 17.0.20.1，Python 3.12.10，PyInstaller 6.16.0。构建分支为 `iteration/v0.6-hybrid`，基于 v0.5 制包器分支。

## 已验证

- Python 15 项通过，覆盖 GPX、离线制包、设备配置，以及在线地址校验、保存和重开项目、生成 URL 和通讯权限。
- 最终代码在 FR255 模拟器运行 61 项 Monkey C 测试，61 PASS，0 failed，0 errors。新增覆盖断连与重连、15 秒超时、30 秒退避、HTTP 错误、异常尺寸、低内存、过期回调、关闭视图后回调、最多四张图片、跨地区离线回退和视口/轨迹/记录对象保持。测试结果以逐项结果及汇总为准，SDK 单元运行器的退出状态不能单独作为通过依据。
- 桌面界面通过实际控件操作验证「在线底图」填写、保存项目、重新打开和清空地址。旧项目未配置地址时仍生成纯离线包。
- 最终独立 EXE 从另一工作目录调用 SDK，成功生成三个地区、四条路线的原项目安装 ZIP。核对项目清单、ZIP 完整性和 PRG SHA-256；私人路线及签名未纳入仓库。
- 同一 EXE 另行生成带在线配置的小范围测试包，编译成功，验证最终打包程序包含通讯实现。

## 原生图片与模拟器边界

`tests/smoke/phone/PhoneSmoke.mc` 在普通应用事件循环中执行生产代码的 `makeImageRequest`、回调、图片缓存与绘制；只用测试变量代替手机连接状态。测试入口使用独立应用 ID，不能作为用户安装包。

测试图片为本仓库公开的固定 PNG，经 HTTPS 获取并缩放为 256×256。这能检查真实图片对象和绘制接口；地图坐标与实际服务瓦片内容的一致性仍需选定图源后验证。测试地址没有写入用户安装包。模拟器从电脑联网，不能验证真实手机蓝牙链路。

原生检查完成两轮各四张图片的接收和绘制，中间断连后离线瓦片已准备，重连后视口保持，输出 `NATIVE_HTTP_FOUR_BITMAPS_DRAWN`、`LOCAL_FALLBACK_DRAW_READY`、`NATIVE_RECONNECT_PASS`。该普通应用检查进程返回 0。

## 待实机验证

- 选择允许本应用访问和署名的 256px WGS84/Web Mercator XYZ 图源，提供 z13/z15，然后在桌面程序填写地址、重新生成安装包。
- 手机 Garmin Connect 保持可用：首次加载、移动、缩放、断开蓝牙、恢复连接和手机断网时的实际延迟。
- FR255 在四张在线图片、离线底图和较长轨迹同时存在时的内存与长时间续航。
- 超出所有已打包地区时，断网应显示「无离线覆盖」并保留轨迹；新下载图片只缓存在运行内存中，重开应用不作为离线地图保留。

参考接口：[Garmin makeImageRequest](https://developer.garmin.com/connect-iq/api-docs/Toybox/Communications.html#makeImageRequest-instance_function)。在线服务不继承桌面下载器的自定义请求头；应先核对服务是否允许这种访问方式。没有指定图源时，本版保持纯离线。
